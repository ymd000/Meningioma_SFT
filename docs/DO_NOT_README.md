## TITANのハンパなさ
このテーマを扱うようになって、まずはひたすらABMILで分類器モデルのcv(crossvalidation)訓練をしていた。  

なぜcvかというと、以下のような理由があった。  
- 1施設しかデータがなかった  
- 全てのデータに対して推論をしたかった（スライドレベルの埋め込みが欲しかった）  

cvの弊害として、**モデルがfoldの数だけできてしまう**ことがある。あと、実装がめんどくさい。  
データセットの一部をテストデータとして使っていないデータで訓練するので、小規模のデータだと過学習がおこりやすい。  

私の場合も例にもれなく、各モデルから得られたスライドレベル埋め込みのumap plotはカオスになってしまった。  
なんならパッチレベル埋め込みの単純平均をスライドレベル埋め込みとしたときのほうがよい感じ。  
分類タスク自体もABMILは単純平均とさほど変わらない。  
ポスター発表の締め切りも1ヶ月ほどである。まずい。  
このままでは「ABMILはfoldごとの一貫性がありませんでした」で終わってしまう。 

ABMILのattention scoreを閾値にして~~誤魔化して~~いい感じにumapを作成してお茶を濁そうとしていところ、メンターから一言。  

「時間まだあるでしょ？TITAN試さないの？」  
「はい。わかりました。」  

TITANとはパッチレベルの埋め込みを入力にしてスライドレベル埋め込みを出力するViTライクなモデルである。  
数十万枚のWSIで訓練されているらしい。なんかすごそうである。  
huggingfaceとgithubのREADMEからおっかなびっくりデータを通してみる。  

やってみてびっくり、umapがきれいにラベルごとに分かれるではないか。 

最初に出力された画像を見たときの感動は忘れられない。  

## バッチエフェクトの女神
データセットが増え、苦しめられたcvをやる必要もなくなり順調に思えた。  

当然現実はそんなはずはなくて、施設間差の影響(バッチエフェクト)が大きく、分類タスクはうまく行くが埋め込みの解析が主観的な評価の域を出ない。  

次の発表まで2週間をきっていた。どうしようか。  

そもそも、施設間差とは染色の具合やビューアーによる画像の色調の差である。  
攻略するには、シンプルに色調の差を補正すれば良い。  
しかしこれは絵画で言うならタッチをかえるようなものだ。  
時間もかかるし、うまく行っているかどうかの判断は職人技である(ハイパラ調整など)。  
めんどくさい。。  

ここでまた鶴の一声。  

「施設で重心揃えるのやった？」  
「はい。やります。」  

重心とはスライドレベルの埋め込みを施設ごとに平均したもののことである。  
画像レベルで補正するのではなく、圧縮したスライドレベル埋め込みで補正するのである。  

これはかなり乱暴である。  
**WSIは数GBほどあるが、これをベクトルに埋め込んだ3,072 bytesほどの情報量だけで調整する**ことを考えたら想像に易いだろうか。  
実装は簡単で計算も大したことはない。やってみる。 

びっくりするくらいうまくいった。  
スライドレベル埋め込みのumap plotはサブタイプごとにきれいに集合した。  
埋め込みをサブタイプごとに集計して距離を測ったらサブタイプが施設ごとのペアをつくった。  
してやったりだ。
